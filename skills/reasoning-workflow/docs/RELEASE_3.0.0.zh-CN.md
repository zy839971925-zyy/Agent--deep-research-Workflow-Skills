# Reasoning Workflow 3.0.0：功能升级说明

> 本地候选版本；尚未推送、提交 PR 或发布到远端。版本号体现本次工作流能力面的大幅扩展，不代表模型研究质量已实测提升。

## 这次为什么是大版本

2.2 已经有较完整的研究前沿、证据溯源、Ultra 重构和跨会话状态机制。3.0 不再叠一层通用流程，而是补上三个真实使用缺口：**研究问题类型不同，调研路径要能切换；面对含糊需求要先自己查证，再只问用户无法替代的关键项；长任务恢复要找回正确材料并重新对齐验收，而不只是读回一段旧摘要。**

## 主要功能变化

- **每轮静默匹配与显式入口。** Portable 入口在宿主保持激活时，对每条直接用户请求先做轻量深度分流；简单任务仍走 Light，不加载整套研究流程。用户直接说“调用我的 workflow skills”即可显式选用该流程，但不会自动升到 Ultra，也不增加权限。要保证每轮触发，宿主必须提供始终生效的系统指令或前置路由器；Skill 描述、普通自动匹配和任务 Profile 路由本身都不能保证它已经被载入。

- **现实问题与技术架构分路、混合问题串联。** 新增触发式研究模式：现实/经验问题先区分描述、因果、机制、预测和价值判断，并让证据方法匹配所声称的结论；技术架构调研从现有仓库、接口、测试和限制出发，用质量属性场景比较不同设计；同时涉及用户价值与系统可行性的任务保留两条证据链，避免把“能做”误当成“值得做”。
- **把架构决策落到可区分的证据。** 结合 SEI 的 ATAM 思路，轻量列出受实际目标驱动的场景、风险、敏感点和取舍；只在关键不确定性值得时做小型可逆原型，不把正式 ATAM 或架构图变成每个开发问题的仪式。
- **证据驱动的先查后问。** 新增 Clarification Gate，把未决信息路由到会话/任务状态、项目材料、当前宿主能力、外部来源、可推导结果或用户本人。只检查与该依赖有关且可能改变结论的证据；只有剩下的用户专属选择会实质改变结果、又不能安全条件化时，才问最小关键问题。重要未知保存在既有任务状态中。类 “Grill Me” 的追问仅在用户要求或开放目标确实需要时启动；澄清不等于授权。
- **长任务更可靠续跑。** 恢复时除检查状态、版本和可能已提交的副作用外，还要在可访问的工作区索引里定位已移动或改名的材料，核对内容/版本/来源，不能只因旧路径失败就宣称文件不存在；在中断、交接、合并或检查点后，把下一步重新绑定到尚未满足的验收条件，丢弃与主目标无关的分支，保留已完成且不受影响的工作。若交接因输入长度被拒绝，应压缩重复上下文但保留目标、约束、证据定位和返回契约，并确认重提已被接收后再继续。
- **加入面向真实使用的场景协议。** 新增十五类 V3 手工评测场景，覆盖现实经验问题、开发前架构、用户需求与技术可行性混合、该问/不该问、产品能力与当前会话不匹配、文件迁移/长任务恢复、局部纠正后的依赖失效、环境版本漂移与根任务取消后的迟到子代理结果。附合成项目与续跑工作区，便于同版本/同宿主/同工具条件做成对比较。
- **把知名方法当作工具而非权威。** 纳入外部视角/参考类别、premortem、Tukey 探索/确认区分、Feynman 的反证诚实原则、Kahneman–Klein 的专家直觉条件、调查测量边界和 ATAM 质量属性情景，并写清适用范围；研究也提示“考虑相反观点”不是万能去偏法。方法只触发与任务相关的证据动作，不模拟“名人思维”，不把人类研究外推成已证明的 AI Agent 效果。
- **把因果模型转成联网检索动作。** 搜索前先选会改变结论的因果边和可观察证据；按效应/比较、机制与时序、竞争解释、边界或负向结果拆分查询，让材料中的术语和检索结果推动下一轮改写；只在接口支持且确有帮助时使用精确短语、站点、日期或文件类型语法。打开原文核对人群、设计、变量和时间范围，区分机制线索与整体因果效应，并按需保留可复现的检索轨迹。系统综述的检索报告规范仅用于相应的系统综述，不给普通网页调研强加来源配额。 详细步骤与方法来源见[因果链联网检索方法](../references/retrieval-and-observation.md#online-search-turn-the-causal-model-into-retrieval-moves)及其[检索方法参考文献](../references/retrieval-and-observation.md#search-method-references)。
- **做实际运行时能力核验。** 产品手册、普通搜索、Deep Research、连接器、多代理和智能 UI 分别对待。增加“此处可用/不可用/未核验”状态和诚实降级：例如 ChatGPT Deep Research 的计划/地区/工作区差异、Claude Research 的 Web Search 要求与移动端 connector 限制、Grok 多代理文档所指的 API beta；不能把产品宣传当成此会话已成功调用。

## 对 2.2 方法的实操复审

这轮按 2.2 Ultra 的方式拆分证据路线、并行查找和交叉核对，能帮助定位研究缺口；但实际使用也暴露出两个值得做成显式能力的地方：材料/搜索结果出现后，模型仍可能把“外部事实可查”误当成“用户需要补充”，或把产品文档描述的功能误当成当前宿主真的开放。原有研究状态还需要把 `verified/assumed/open/conflicted/deferred` 与受影响分支绑定，才能在续跑时精确恢复。V3 因此新增 resolver-first 提问、宿主能力状态和依赖级续接场景。这是一次流程复盘，不是对模型质量的对照评测。

## 方法依据及其限度

完整来源、方法触发条件和适用边界见 [研究模式与方法](../references/research-modes-and-methods.md)。以下只列本版核心依据。

- Kazman 等人的 [ATAM](https://www.sei.cmu.edu/library/the-architecture-tradeoff-analysis-method/) 用质量属性场景揭示架构风险和取舍；这里采用轻量启发，不要求每次正式开展全套评估。
- Kahneman 与 Lovallo 的[外部视角/参考类别](https://doi.org/10.1287/mnsc.39.1.17)可帮助审视容易受内部计划偏差影响的工期/成本预测，但需要真正可比的参照组，不是通用预测公式。
- Klein 的 [Project Premortem](https://hbr.org/2007/09/performing-a-project-premortem)用于生成可检验的失败假设，不是风险概率估计。
- Tukey 的探索性与确认性分析区分提示：发现模式与独立验证不能混为一谈；AAPOR 的[调查研究最佳实践](https://aapor.org/standards-and-ethics/best-practices/)补充了调查抽样、问题措辞和透明报告的边界。Feynman 的[科学诚信讲座](https://calteches.library.caltech.edu/51/2/CargoCult.htm)提醒报告会削弱解释的事实和替代原因；这不是逐条添加反证清单的配额。
- Mark、Gudith 与 Klocke 的[中断工作实验](https://ics.uci.edu/~gmark/chi08-mark.pdf)提供了人类任务切换的设计参考，但不证明这些检查点会提升模型表现。

## 验证边界

本地检查通过后可证明的是测试代码、格式、引用路由、文件/归档一致性和校验和，不代表 AI Agent 实际都能遵循。V3 的场景尚未在真实模型上运行和盲评；本版不声称调研质量、成本、速度或长期任务成功率得到提升。产品/harness 可用性仍以运行时实际提供的功能为准。
